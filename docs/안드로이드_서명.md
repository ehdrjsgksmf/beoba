# 안드로이드 서명 — 조사 결과

**아직 열쇠를 만들지 않았습니다.** 이 문서는 만들기 전에 알아야 할 것을
적어 둔 것입니다. 만드는 순서는 사람이 정합니다.

## ★ 먼저 — 잃어버리면 어떻게 되나

**이것이 이 문서의 이유입니다.** 다음 사람이 「안 쓰는 파일 같은데」 하고
지우지 않게 하려고 적습니다.

```
업로드 열쇠(우리가 가짐)      잃어버려도 앱을 잃지 않습니다.
                            구글에 새 인증서를 내고 재설정을 요청합니다.

앱 서명 열쇠(구글이 가짐)     Play 앱 서명을 쓰면 구글이 보관합니다.
                            우리가 잃어버릴 것이 없습니다.

★ 우리가 직접 관리하는 경우   구글 문서 그대로 — 「이 열쇠는 Play 앱 서명
                            없이 직접 관리하다가 잃어버리면 재설정할 수
                            없습니다.」 그 앱을 **다시는 업데이트하지
                            못합니다.** 새 앱으로 올려야 하고, 설치한
                            사람들은 따라오지 않습니다.
```

**그래서 Play 앱 서명을 씁니다.** 우리가 쥐는 것은 업로드 열쇠 하나이고,
그건 잃어버려도 되돌릴 길이 있습니다.

★ **그렇다고 업로드 열쇠를 아무렇게나 두어도 된다는 뜻은 아닙니다.**
재설정은 사람이 신청하고 구글이 처리하는 절차라 시간이 걸립니다. 급한 수정을
내야 하는 날 그 절차를 밟게 되면 며칠이 날아갑니다.

**지우지 마세요. 그리고 올리지도 마세요.**
`docs/원격에_올리지_않는_것.md` 가 올리는 쪽을 막습니다. 지우는 쪽을 막는
것은 이 문장뿐입니다.

## 지금 설정

`apps/beoba/android/app/build.gradle.kts` 는 Flutter 기본 그대로입니다.

```
buildTypes {
    release {
        // TODO: Add your own signing config for the release build.
        signingConfig = signingConfigs.getByName("debug")
    }
}
```

**릴리스가 디버그 열쇠로 서명됩니다.** 이 상태로는 스토어에 못 올립니다.
`signingConfigs` 블록도, `key.properties` 를 읽는 코드도 아직 없습니다.

무시 목록은 이미 되어 있습니다 — `apps/beoba/android/.gitignore` 가
`key.properties` · `**/*.keystore` · `**/*.jks` 를 막고, 위쪽
`apps/beoba/.gitignore` 도 같은 것을 막습니다. **다만 무시 목록은
한 번 추가된 파일을 못 막습니다** — 그래서 검사 (ai) 가 따로 봅니다.

## Play 앱 서명이 무엇인가

열쇠가 **둘**입니다. 헷갈리면 위험한 쪽을 잘못 다루게 됩니다.

| | 누가 가지나 | 무엇에 쓰나 |
|---|---|---|
| **업로드 열쇠** | **우리** (`.jks`) | 우리가 낸 것이 맞는지 구글이 확인 |
| **앱 서명 열쇠** | **구글** | 사용자 기기로 가는 APK 에 최종 서명 |

구글 문서는 「최대한의 보안을 위해 업로드 열쇠와 앱 서명 열쇠는 서로 달라야
합니다」라고 적고 있습니다.

앱 서명 열쇠는 셋 중 하나로 정합니다 — **구글이 만들게 두거나**(기본이자
권장), 우리 열쇠를 올리거나, 같은 계정의 다른 앱과 같은 것을 쓰거나.
**구글이 만들게 두는 쪽을 씁니다.**

## 새 앱이 지나야 하는 문

```
2021년 8월부터   새 앱은 Android App Bundle(.aab) 로만 낼 수 있습니다.
                APK 로는 새 앱을 못 냅니다.
AAB 를 올리려면   Play 앱 서명에 등록돼 있어야 합니다.
새로 만드는 앱은   Play Console 문서 기준으로 구글이 만든 열쇠로 자동 등록됩니다.
```

★ 「AAB 를 올리려면 등록돼 있어야 한다」는 **구글 공식 문서 문장이 아니라
개발자 커뮤니티에서 반복해서 나오는 오류 메시지**에서 확인한 것입니다.
Play Console 이 그 메시지를 직접 냅니다. 등록 화면은 계정을 만든 뒤에
직접 보고 확인하세요.

그리고 빌드 명령이 달라집니다.

```
지금 CONTRIBUTING.md 에 적힌 것   flutter build apk --release      실기기에 붙일 때
스토어에 낼 때              flutter build appbundle --release
```

## 만들 때 — 절차 (아직 하지 마세요)

Flutter 문서가 적어 둔 그대로입니다.

```
keytool -genkey -v -keystore <집>/upload-keystore.jks -keyalg RSA \
        -storetype JKS -keysize 2048 -validity 10000 -alias upload
```

Windows 는 `$env:USERPROFILE\upload-keystore.jks` 입니다. 그리고
`apps/beoba/android/key.properties` 를 만들어 넉 줄을 적습니다 —
저장소 비밀번호 · 열쇠 비밀번호 · 별칭(`upload`) · 열쇠 파일 자리.
Windows 경로는 역슬래시를 **두 개씩** 씁니다.

★ **`key.properties` 도 `.jks` 도 저장소 안에 두지 않습니다.** 집
디렉터리처럼 저장소 **바깥**에 두고 `storeFile` 로 가리킵니다. 안에 두면
누군가 `git add -f` 한 번으로 끝납니다.

그다음 `build.gradle.kts` 가 그 파일을 읽게 합니다. ★ **한 가지를 Flutter
문서와 다르게 합니다** — 문서 그대로 넣으면 `key.properties` 가 없는 기계에서
릴리스 빌드가 깨집니다. 없으면 디버그 열쇠로 떨어지게 두고, **CI 의 배포
단계에서만 진짜 열쇠를 요구합니다.** 그래야 열쇠 없는 사람도 계속 일합니다.

## CI 에서 서명하려면

열쇠 파일을 저장소에 못 넣으므로 **GitHub 비밀에 base64 로 넣고 빌드할 때
풀어 씁니다.** 러너 안에만 잠깐 생기고 커밋되지 않습니다.

```
비밀 넷   ANDROID_KEYSTORE_BASE64   .jks 를 base64 로 인코딩한 것
          ANDROID_KEYSTORE_PASSWORD
          ANDROID_KEY_ALIAS         upload
          ANDROID_KEY_PASSWORD
단계      base64 로 풀어 파일로 쓰고, key.properties 를 그 자리에서 적는다
```

웹 배포와 같은 꼴입니다 — **열쇠가 없으면 그 단계는 통째로 건너뜁니다.**
