# 원격에 올리지 않는 것

**이 문서가 목록이고, 검사 (ai) 가 이 문서를 읽습니다.** 두 벌로 두지
않습니다 — 사람이 읽는 목록과 기계가 보는 목록이 따로 있으면 반드시 한쪽이
낡습니다(DECISIONS 126번).

## 왜 이 검사가 따로 있나

`.gitignore` 로는 부족합니다. **한 번이라도 `git add` 된 파일은 그 뒤로
`.gitignore` 를 무시하고 계속 추적됩니다.** 그래서 무시 목록이 아니라
**실제로 추적 중인 것**(`git ls-files`)을 셉니다.

그리고 이 자리는 **되돌릴 수 없습니다.** 한 번 원격에 올라가면 지워도 이력에
남습니다. 다른 검사는 틀리면 고치면 되지만 이건 고칠 수 없습니다.

## 경로 — 추적 중이면 안 되는 것

`/` 로 끝나면 그 아래 전부, `*.` 로 시작하면 확장자, 그 밖은 파일 이름입니다.

```경로
.env
.env.*
law/
welfare/
*.pdf
*.csv
*.gz
*.zip
*.key
*.pem
*.p12
*.jks
*.keystore
*.crt
*.pfx
key.properties
*.der
```

★ **안드로이드 서명 열쇠는 만들기 전에 미리 막았습니다.** 만든 뒤에 넣으면
늦습니다 — 만든 날 한 번 `git add` 되면 그날로 끝입니다.
`.jks` · `.keystore` · `key.properties` 가 그것입니다.
**그 파일은 올려도 안 되고 지워도 안 됩니다** — 왜 지우면 안 되는지는
`docs/안드로이드_서명.md` 에 적어 두었습니다.

원문(`law/` · `welfare/`)을 막는 이유는 비밀이라서가 아닙니다. **저작권과
용량**입니다 — 그리고 저장소에 없어도 앱이 도는 것이 이 리포의 규칙입니다
(커밋된 JSON 이 진짜 데이터다, CONTRIBUTING.md).

```허용
.env.example
```

`.env.example` 은 **키 이름만 있고 값이 없습니다.** 값을 적는 순간 아래
「내용」 규칙에 걸립니다.

## 내용 — 추적 중인 파일 안에 있으면 안 되는 것

**이름이 아니라 값을 찾습니다.** `apiKey` 라는 낱말은 코드에 있어도 됩니다.
`apiKey = "실제값"` 이 문제입니다. 이름만 막으면 코드가 자기 필드를 못
부르고, 그러면 사람이 검사를 끕니다.

```내용
DATA_GO_KR_KEY=.+
serviceKey=[A-Za-z0-9%+/=_-]{20,}
BEGIN [A-Z ]*PRIVATE KEY
AKIA[0-9A-Z]{16}
gh[pousr]_[A-Za-z0-9]{20,}
xox[baprs]-[A-Za-z0-9-]{10,}
AIza[0-9A-Za-z_-]{30,}
storePassword=.+
keyPassword=.+
```

★ **이 문서 자신은 내용 검사에서 뺍니다.** 여기에 적힌 것은 찾는 규칙이지
값이 아닙니다. 빼지 않으면 목록을 적는 순간 검사가 자기 목록에 걸립니다.

## 늘릴 때

새 규칙을 위 울타리 안에 한 줄 더 적으면 끝입니다. **검사 코드는 안
고칩니다.** 다만 규칙을 늘렸으면 `git ls-files` 가 이미 그것을 들고 있지
않은지 먼저 보세요 — 늘리자마자 빨간불이면 **이력에도 있는 것**이고, 그때는
지우는 것으로 끝나지 않습니다.
