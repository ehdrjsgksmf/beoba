# 버바 (beoba) — 포트폴리오

변호사를 쓰기 어려운 사람에게, 법에 정해진 기한과 비용과 절차를
**조문 원문과 함께** 알려주는 앱

Flutter (Android · Web) · 1인 개발

---

## 0. 한 장으로

| | |
|---|---|
| **무엇** | 법률 문제가 생겼을 때 **오늘 무엇을 해야 하는지**와 **언제까지인지**를 조문 원문과 함께 알려주는 앱 |
| **누구에게** | 변호사 선임이 어려운 사람. 민사 사건 상당수가 양쪽 다 변호사 없이 진행됩니다 |
| **핵심** | 무엇을 하는지보다 **무엇을 하지 않는지**가 이 제품을 정의합니다 |
| **상태** | 미출시 · 사용자 0명 · 웹 릴리스 빌드 통과 · 정확도와 구조를 세우는 단계 |

```
법령 147개 · 인용 조문 305개 · 원문 못 받은 인용 0건 · 법령 PDF 167개
법률 분야 15개 · 연결한 복지 제도 461건
빌드를 막는 검사 41가지 · 자동 테스트 2,039건 · 설계 결정 기록 290건
```
| 하는 것 | 하지 않는 것 |
|---|---|
| 법에 정해진 **기한**을 오늘 기준으로 계산 | 이길지 질지 **예측** |
| 필요한 **서류와 드는 돈**을 절차별로 계산 | 법률 **상담** · 서류 대필 |
| **조문 원문**을 화면에 그대로 제시 | 특정 변호사 소개 |
| 무료 공적 창구 안내 · 받을 수 있는 복지 연결 | **AI · 외부 추론 엔진** — 하나도 쓰지 않습니다 |

## 1. 문제 — 왜 이렇게 만들었나

법률 정보는 이미 인터넷에 넘칩니다. 없는 것은 **「어느 것이 내 사건에 맞는지 ·
언제까지인지 · 얼마가 드는지」** 입니다.

그리고 기존 법률 챗봇·AI 서비스는 **그럴듯한 답을 만들어냅니다.**
법률 분야에서 이건 치명적입니다.

- 사용자가 **검증할 수 없습니다** — 법을 모르니까 물어본 것입니다
- 기한을 놓치면 **되돌릴 수 없습니다** — 소멸시효, 제소기간, 신청기한

그래서 이 앱은 「지어내지 않는 것」을 **사람의 주의가 아니라 빌드로 강제**했습니다.

> **모르는 것은 실패가 아니라 경고로 잡습니다.**
> 모르는 것을 막으면 지어내게 되기 때문입니다.

## 2. 핵심 설계 — 「분야는 코드가 아니라 데이터다」

법률 분야를 코드가 아니라 **JSON 데이터**로 정의합니다.

```
packages/domain_data/assets/domains/      — 분야 데이터 1.2MB, 전부 조문 대조를 거친 것
  debt_recovery.json         돈을 못 받았어요
  unfair_dismissal.json      갑자기 나가라고 했을 때
  jeonse_fraud.json          전세사기
  _shared_crisis.json        위기 감지 · 브로커 경보 (공통)
  … 모두 15개 분야
```

한 분야의 구성:

```
질문(intake) · 기한(deadlines) · 비용(costs · costScenarios)
준비물(documents) · 절차(procedures) · 관할(jurisdiction)
주의(cautions) · 브로커 경보(brokerAlerts) · 공적 창구(publicChannels)
소멸시효(limitationRules) · 근거(legalBasis · alsoBasis) · 이 길을 만드는 법(pathLaw)
```

**효과** — 두 번째 분야를 만들 때 **새 모델 클래스를 하나도 만들지 않았습니다.**
부족한 곳 셋은 기존 모델에 필드를 더하거나 이름 규칙으로 메웠습니다.
분야를 늘리는 비용이 선형이 아니라 체감합니다.

### 패키지 구조 — 계산이 화면을 모릅니다

```
packages/domain_data/   순수 Dart · Flutter 의존 금지
                        모델 · 로더 · 스키마 검증 · 분야 JSON
packages/engines/       순수 Dart · Flutter 의존 금지 · 분야 무관
                        기한 · 비용 · 기간 · 관할 계산 엔진
apps/beoba/             Flutter 앱 (화면만)
```

**「Flutter 의존 금지」는 주석이 아니라 pubspec 에 박힌 제약입니다.**
두 패키지의 의존성 목록에 Flutter 가 없어서, 실수로 위젯을 import 하면
컴파일이 안 됩니다.

여기서 얻는 것 셋:

- **계산 로직을 그대로 옮길 수 있습니다** — 서버 · CLI · 다른 플랫폼 어디로든
- **테스트가 Dart VM 에서 빠르게 돕니다** — 화면을 띄우지 않고 계산만 검증
- **화면 없이 검증 도구를 돌립니다** — 분야 JSON 전수 검증이 앱 빌드와 무관하게 CI 에서

## 3. 기술 스택

**언어는 Dart 하나입니다.** 앱 · 계산 엔진 · 데이터 모델 · 검증 도구까지 전부
같은 언어로 씁니다. 법률 계산은 한 곳에서 값이 어긋나면 전체가 틀리기 때문에,
언어 경계를 만들지 않았습니다.

| 층 | 무엇 |
|---|---|
| 언어 | **Dart** (SDK ^3.13) |
| 프레임워크 | **Flutter** — Android · Web |
| 모노레포 | **melos** ^8.3 + Dart pub workspace |
| 모델 생성 | **freezed** ^3.0 · **json_serializable** ^6.8 (build_runner) |
| 상태 관리 | **flutter_riverpod** ^3.4 |
| 라우팅 | **go_router** ^17.5 |
| 조건 평가 | **JsonLogic** — 데이터가 화면 분기를 정합니다 |
| 정적 분석 | `dart analyze --fatal-infos` · `unused_import` · `dead_code` 를 **에러로** |
| 테스트 | `test` (Dart VM) · `flutter_test` (위젯 · 경로) |
| CI | **GitHub Actions** |
| 외부 API | 공공데이터포털 — 한국천문연구원 특일 정보 · 중앙부처 복지서비스 |

### 정적 분석을 일부러 엄하게

```yaml
analyzer:
  errors:
    unused_import: error
    unused_local_variable: error
    dead_code: error
```

보통 경고로 두는 셋을 **에러로 올렸습니다.** `dead_code` 가 특히 중요합니다 —
법률 데이터에서 죽은 코드는 **화면에 안 나오는 안내**를 뜻하고,
그건 사용자가 정보를 못 받는다는 뜻이기 때문입니다.

### CI 파이프라인

```
정적 분석 (3패키지, info 도 실패)
  → 코드 생성 (freezed · json_serializable)
  → 테스트 (Dart VM + Flutter 위젯 + 경로)
  → 분야 JSON 전수 검증
  → 웹 릴리스 빌드
```

마지막 단계에 이유가 있습니다.

> 테스트는 Dart VM 에서 돈다. 웹은 int 가 JS 실수(2⁵³)라 계산이 다르게 깨질 수
> 있고, 그건 **릴리스 컴파일에서만** 드러난다.

인지대 · 송달료처럼 **원 단위가 어긋나면 안 되는 값**을 다루기 때문에
CI 마지막에 넣었습니다.

### AI · 외부 추론 엔진 없음

LLM, 머신러닝 모델, 외부 추론 API를 **하나도 쓰지 않습니다.**
같은 입력에는 언제나 같은 답이 나옵니다.

이건 성능 문제가 아니라 **검증 가능성** 문제입니다 — 사용자가 화면에서
조문 원문을 보고 **스스로 확인할 수 있어야** 하기 때문입니다.

## 4. 근거 검증 파이프라인 — 이 프로젝트의 본체

### 4-1. 원문 강제

화면에 법 이야기를 낼 때는 **조문 원문을 그대로** 싣습니다.
요약 · 해설로 대신하지 않습니다.

```
법령 147개 · 별표 12개 · 인용 조문 305개 · 원본 못 받은 인용 0건 · 법령 PDF 167개
```

**「0건」은 사람이 세는 것이 아니라 빌드가 막습니다.**
원문을 확보하지 못한 조문을 인용하면 컴파일이 실패합니다.

### 4-2. 세 층으로 나눠 표시 — 그림 없이 글자로

| 표시 | 뜻 | 화면 |
|---|---|---|
| **법에 있는 내용** (채운 면) | 조문에 그대로 있는 것 | 조문 원문 첨부 |
| **적용될 가능성** (옅은 면 + 실선) | 조건 + 결과 | 조건을 명시 |
| **확인 안 된 것** (흰 면 + 점선) | 아직 근거를 못 찾은 것 | **화면에 나가지 않음** |

이모지를 쓰지 않습니다. 초록 네모에 체크가 들어가면 「다 했다」로 읽히기
때문입니다. 대비를 직접 재서 WCAG 를 맞추고, **흑백으로 바꿔도 세 층이
구분되는지** 픽셀로 검사합니다.

「확인 안 된 것」은 사라지지 않습니다. `verification.status` 와
`openPart`(무엇이 아직 열려 있는지)로 데이터에 남아, 나중에 자료를 받으면
그 자리를 채웁니다.

### 4-3. 판본 추적

법령은 계속 개정됩니다. 낡은 조문으로 계산하면 사용자가 손해를 봅니다.

- 인용한 모든 법령 · 별표의 **판본(호수 + 시행일)** 을 매니페스트로 관리
- **별표는 별표 단위로** 판본을 답니다 — 같은 법인데 본문과 별표의 개정일이 다릅니다
  (각급법원법은 [별표 1] 과 [별표 5] 의 시행일이 다릅니다)
- 법률의 별표는 자기 개정일을, 예규 · 고시의 별표는 본체를 따릅니다
- **매주 금요일** 전체 대조
- 한시법의 만료일과 **시행 예정 개정**을 데이터에 적어 두고, 그날이 되면
  검사가 빨개집니다 (실제로 전기통신금융사기 특별법의 낱말 갈이가 시행된 날
  게이트가 그대로 멈췄습니다)

### 4-4. 시행일과 적용례

조문이 오늘 시행 중이어도 **내 사건에 적용되는지는 따로**입니다.

- 관할표에 이름이 있어도 시행일이 미래면 없는 법원으로 다룹니다
- 부칙의 **적용례**를 읽습니다 (민사집행법 시행령 부칙 제2조 — 시행일 이후
  접수된 압류부터 새 금액 적용)
- 압류 금액을 낼 때 **압류가 언제 들어왔는지**를 묻고, 그 전이면 금액을 내지 않습니다

### 4-5. 인용 점검 — 우리 문장이 조문을 넘는가

원문을 확보하는 것과, **우리가 쓴 문장이 그 조문이 말한 범위 안에 있는가**는
다른 문제입니다. 그래서 인용 하나하나를 조문 조각과 맞대 보는 장부를 따로 둡니다.

| | | |
|---|---|---|
| 인용 전체 | 662 | 우리 문장 한 벌 × 조문 한 조각 |
| 표시된 것 | 215 | 자리로는 131곳 |
| 사람이 본 자리 | 25 | 고쳤다 6 · 헛표시 17 · 두고 본다 2 |
| **안 본 자리** | **110** | ← 톱니(ratchet)가 여기 걸려 있습니다 |

**「표시 수」를 지표로 쓰면 고칠수록 숫자가 올라 진도를 못 잽니다.**
그래서 톱니를 **「아직 안 본 것」** 에 걸었습니다. 줄어드는 숫자는 그것 하나뿐입니다.

## 5. 품질 장치 — 빌드를 막는 검사 41가지

사람이 매번 기억할 수 없는 규칙은 **전부 기계가 강제**합니다.
검사기 한 파일이 7,000줄이고, 검사는 `(a)` 부터 `(ap)` 까지 41가지입니다.

| 검사 | 무엇을 막나 |
|---|---|
| 원본 미확보 인용 | 원문 없는 조문 인용 → **실패** |
| 조문 꼴 전수 검사 | 저장소 전체(코드 · 데이터 · 문서)에서 「제N조」를 찾아 매니페스트 대조 |
| 별표 등록 검사 | 등록 안 된 별표 인용 → **실패** |
| 도달 가능성 검사 | 어떤 답 조합으로도 화면에 안 나오는 항목 → **실패** |
| 이름 규칙 강제 | `passed:<기한 id>` 의 오타 → **실패** |
| 원문 무결성 | 근거 원문 안에 토큰 · 밑줄 삽입 → **실패** |
| 금지 문구 | 「이길 수 있습니다」 · 「하세요」(권유) · 「무조건」 → **실패** |
| AI 표기 | 「AI」 · 「인공지능」이 화면에 등장 → **실패** (실제로 안 쓰므로) |
| 라우트 데이터 | 브라우저 히스토리에 남는 방식의 데이터 전달 → **실패** |
| 개인정보 방침 (ah) | 방침의 문장이 거짓이 되면 **몇 번 절인지** 말하며 **실패** |
| 인용 점검 (al) | 우리 문장이 조문을 넘는가 — 「안 본 자리」에 톱니 |
| 같은 조문 (ak) | 두 분야가 같은 조문을 인용하면 ① 원문 조각 ② 우리 문장을 맞대 봄 |
| 카드가 선 자리 (am) | 「이 카드는 무엇 위에 서 있는가」 — 근거 없는 카드를 잡음 |
| 한시법 · 시행예정 (an · z) | 날짜가 바뀌면 그날 빨개집니다 |
| 정답지(골든셋) | 계산 결과 회귀 → **실패** |
| 항목 0개 섹션 | 빈 카드를 그리는 것 → **실패** |

### 실제로 이 장치들이 잡은 것

개발 과정에서 **「통과」가 「아무것도 안 셌다」였던 경우**를 여러 번 발견하고
구조를 고쳤습니다.

- 「자유 입력이 어디에도 안 남습니다」 → 라우터가 **웹 브라우저 히스토리에 남기고 있었음**
- 「배율 200%에서 안 깨집니다」 → 테스트 하네스가 화면 크기를 덮어써서
  **화면 크기 · 자판을 한 번도 검사하지 않았음**
- 「원본 못 받은 인용 0건」 → 용어집이 인용한 조문을 매니페스트가 읽지 않았음
- 「기한 계산 정상」 → 기한이 참이 되는 조건과 차단 화면 조건이 같아,
  **가장 급한 기한 둘이 코드상 도달 불가능**했음
- 「분류기 정확도 상승」 → 정답지가 **자기 분야가 걸렸는지만** 보고
  다른 분야도 같이 걸리는지는 아무도 안 봤음 (참 예문 8건이 중복 적중)

네 번째 건은 화면을 거쳐 결과까지 가는 **경로 테스트**가 없어서 445건의 통과가
가려 준 것이었습니다.

## 6. 법적 경계를 아키텍처에 박음

변호사법이 정한 선을 **문구 검사와 테스트로** 지킵니다.

- 첫 화면의 「법률 상담이 아니라, 순서를 짚어드리는 도구예요」
  — **테스트가 이 문장의 존재를 잠급니다**
- 「이길지 질지는 알려드릴 수 없어요」 — 같음
- 승패 예측 · 법원 이름 단정 · 갈래 선택을 **하지 않는 것**이 데이터 규칙
- 근거가 조문에 없으면 **말하지 않습니다.** 해석이 필요한 자리는 공적 창구로 넘깁니다
  (예: 「상속을 포기하면 다음 순위 가족에게 넘어간다」는 조문에 없는 해석이므로
  화면에 내지 않고 창구로 안내)

화면 문구를 짓게 만든 조문(**변호사법 제34조 · 제109조 · 제112조**)도 원문을
확보해 관리합니다 — 근거가 화면에 안 보인다고 근거가 아닌 것은 아니기 때문입니다.

## 7. 개인정보 — 코드가 먼저 지킨 뒤에 말합니다

화면에 「적어주신 내용은 저장하지 않아요」라고 쓰기 **전에** 코드를 검사했습니다.

- 입력 저장 코드 **0줄**
- 분석 · 크래시 리포트 SDK **0개**
- 서버 전송 **0건**
- 라우트로 데이터를 나르는 것을 **빌드가 금지**

개인정보처리방침의 문장이 거짓이 되면, 검사가 **방침의 몇 번 절이 깨졌는지**
말하며 빌드를 멈춥니다.

우리가 못 막는 것(휴대폰 자판의 학습 사전)은 **못 막는다고 말하고
어디서 지우는지 알려줍니다.**

## 8. 접근성 — 읽을 수 있어야 정보입니다

- 시스템 글자 크기 **200%** 에서 깨지지 않음 (테스트로 잠금)
- **쉬운 말 모드** — 낱말이 아니라 **문장**을 바꿉니다. 켠 것을 기기가 기억합니다
- **밀도 예산 4.12화면** — 한 갈래가 몇 화면이 되는지를 재서 상한을 둡니다.
  카드를 더하면 그만큼 어디선가 접어야 합니다
- 노치 · 상태표시줄 · 제스처 바 대응 · 자판이 올라온 상태에서 버튼이 눌리는지 검사
- 어려운 용어에 **점선 밑줄 + 바텀시트** — 시트 안에 조문 원문과 시행일까지
- 용어는 검색이 아니라 **마크업으로 지정** — 「주소가」에서 「소가」를 잘못 잡는
  오탐이 설계 단계에서 불가능
- 결과를 **종이 한 장으로 정리해 가져가기** — 창구에 들고 갈 수 있게

## 12. 확장 계획

### 남은 분야 일곱

교통사고 · 뺑소니 · 폭행 · 상해 · 스토킹 · 가정폭력 · 학교폭력 · 의료사고 ·
과태료 이의 등 — 법령 자료는 상당수 확보되어 있습니다.

**한 분야당 필요한 것은 코드가 아니라 조문 대조입니다.**

### 데이터가 쌓이면 열리는 층

조문에 없어서 못 채운 칸(법원 제출 서류 통수, 실제 송달료, 창구에서 실제로
해주는 것)을 **겪은 사람의 답**으로 채웁니다.

- 커뮤니티가 아니라 **「우리가 열어 둔 칸만 묻기」** — `openPart` 로 무엇이
  열려 있는지 기계가 이미 알고 있습니다
- 표시 층이 하나 늘어납니다: **겪은 분들이 알려준 것 (N명)**
- 「법에 있는 내용」을 절대 넘지 못합니다. 우리 주장이 아니라 관측치이므로
  법적 위험이 없습니다

### AI를 붙일 경우

현재 **AI를 전혀 쓰지 않습니다.** 자유 입력 이해에 AI를 붙이면
「인공지능 발전과 신뢰 기반 조성 등에 관한 기본법」 제31조의 사전 고지 · 표시
의무가 켜집니다(조건부). 그 조건과 대응을 미리 문서화해 두었습니다.

붙이더라도 **AI는 문 앞까지만 데려다주고 안에는 들어오지 않습니다** —
분류에만 쓰고, 답을 만들지 않습니다.

## 13. 이 프로젝트에서 가장 오래 가는 것

코드보다 다음 셋이 더 오래 갑니다.

**① 조문 원문 147개 법령 + 판본 추적 체계**
법령은 개정되지만 추적 구조는 남습니다.

**② 설계 결정 290건 — 되돌릴 조건까지**

> 시효는 계산하지 않고 갈래로 낸다. 우리가 고르면 틀릴 수 있다
> 하드스톱은 해 줄 게 하나도 없을 때만이다. 하나라도 있으면 먼저 보여준다
> 모르는 값은 빈 카드로 두지 않고 카드를 안 그린다. 빈 칸은 0으로 읽힌다
> 화면이 하는 약속은 코드가 먼저 지킨 뒤에 쓴다
> 테스트 하네스가 실기기의 조건을 지우면, 테스트 수는 늘어도 본 것은 없다
> 모르는 것을 막으면 지어내게 된다. 모르는 것은 경고로, 틀린 것은 실패로 잡는다
> 표시 수는 진도를 못 잰다 — 톱니를 「안 본 것」에 건다

**③ 「지어내지 않는다」를 강제하는 검사 41가지**
법률 분야뿐 아니라 **의료 · 세무 · 행정 등 정확도가 생명인 어느 분야에도
옮길 수 있는 구조**입니다.
